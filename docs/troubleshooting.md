# Troubleshooting

Problems people hit with this stack, roughly in the order they hit them.

---

## Setup

**`dx and dioxus versions are incompatible`**
The CLI and the `dioxus` crate must be the same version. `Cargo.toml` pins
`dioxus = "=0.7.9"`; install the matching CLI:

```bash
cargo binstall dioxus-cli@0.7.9 --force
```

When you upgrade Dioxus, bump `dioxus`, `dioxus-fullstack`, `manganis`, and the
CLI together.

**`Failed to connect to SurrealDB`**
The database is not running, or `.env` points somewhere else. `just db-up`, then
check `SURREALDB_HOST` and `SURREALDB_PORT` in `.env` agree. If port 8000 is
taken by another project's database, set both to a free port.

**SurrealDB exits with `Permission denied (os error 13)`**
The container writes as a non-root user and cannot write to its data directory.
`compose.yml` uses a bind mount to `./data` for this reason. Delete `./data` and
`just db-up` again.

**`asset!` cannot find `/assets/tailwind.css`**
It is generated by `dx` on build and gitignored. Run `just dev` once, or create
an empty file: `touch assets/tailwind.css`. CI does the latter.

**`just setup` fails at `lefthook install`**
Lefthook needs a git repository. `git init` first, or skip the hooks.

## Building

**Works in `cargo check`, fails in CI**
`cargo check` builds only the web feature set. Run `just check` for all three.
The usual culprit is a server-only type (`surrealdb::..`, `axum::..`) used
outside `#[cfg(feature = "server")]`, or a plugin call not gated for the server
build.

**`unused` warnings for an insert struct on client builds**
Insert shapes like `CreateNote` are only constructed inside server function
bodies, which client builds replace with an HTTP call. Mark them
`#[cfg_attr(not(feature = "server"), allow(dead_code))]`, as the template does.

**Clippy: `this MutexGuard is held across an await point` (on a signal)**
You are holding a signal read or write across `.await`. Read the value into a
local first:

```rust
let id = selected_id(); // not: selected_id.read() held across the await
save(id).await;
```

## Running

**Everything says 401 after restarting `dx serve`**
Your cookie names a session the server no longer resolves. The splash handles
this on the next page load; reload the page.

**`Error deserializing data ... expected ..` in the browser console on load**
Server rendering and hydration disagree about the order of streamed data. The
usual cause is a `document::Link`, `document::Title`, or similar rendered
*beside* a component that calls `use_server_future` rather than inside it. Keep
head elements below `AppStateProvider`, as `ThemedShell` does.

**A click handler does nothing, only in the browser build**
Hydration failed on that subtree, almost always because markup is behind a
`cfg` that differs between the server and the client. Gate the call, not the
`rsx!`. See [native-plugins.md](native-plugins.md).

**`already borrowed: BorrowMutError` panic**
A signal borrow was held while the same signal was written, most often across an
`.await`. See the clippy entry above.

**A hook panics when a screen changes state**
A `use_*` call is inside an `if` or `match` arm. Hooks run in the same order on
every render; call all of them at the top of the component and branch on the
results.

**The page stretches edge to edge on desktop, or stays phone-width**
Responsive rules query the g3-ui shell with `@container g3-app-shell`, not the
viewport. If you added a media query, convert it.

**The theme toggle flips back by itself**
Something re-applies the stored preference after the user changed it. Apply the
user's saved appearance once — see `AppStateProvider` in `src/state.rs`.

## Transitions

**A sheet slides in sideways instead of rising**
Some route has `forward = ThatSheet`. `forward` overrides the destination's
layer; use it only between two `pushed` routes.

**A filter tap cross-fades the whole page**
The route needs `replace`: `#[transition(root, replace)]`.

**Back returns to the splash or sign-in screen**
The destination needs `replaces = (Splash, SignIn)`.

**No animation at all**
The navigation used `navigator.push` instead of `animated_navigate`, the browser
lacks the View Transitions API, or the OS has reduced motion on. The last two
fall back to an instant navigation by design.

**`#[end_layout]` parse error**
A trailing `#[end_layout]` with no routes after it is rejected. Leave the last
layout open.

## Mobile

**Sign-in works, every call after it is a 401**
The session cookie is not being kept. `dioxus_cookie::init()` must run in
`main` before `dioxus::launch`, and the `mobile` feature must be enabled.

**The app cannot reach the server on a device**
`localhost` on a phone is the phone. In development, `dx serve --platform ..`
finds your machine; a manually set `SERVER_URL` needs a LAN address or a tunnel.
Release builds require HTTPS.

**Release build panics at launch: `SERVER_URL must be set`**
Set it when bundling: `SERVER_URL=https://app.example.com dx bundle ..`.

**A native plugin does nothing**
It probably has no implementation on that platform — plugins compile to no-ops
there by design. Check the table in [native-plugins.md](native-plugins.md), then
the permissions it needs in `Dioxus.toml`.

**Storage fails on the iOS simulator with `-34018`**
Keychain access needs a provisioned build. Test storage on a device.
